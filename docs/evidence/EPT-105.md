Las trazas fallaron en `run-stage.py`, línea 41 del commit probado: `os.killpg(pid, 0)` produjo `PermissionError: [Errno 1] Operation not permitted`. El [manual Apple kill(2)](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/kill.2.html) diferencia EPERM de ESRCH y explica que la señal 0 solo comprueba errores. El [código Apple XNU, `killpg1`](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_sig.c) filtra miembros zombie y puede devolver EPERM cuando un grupo existente no tiene miembros señalizables. Esto fundamenta que **EPERM no demuestra ausencia ni permite declarar cleanup aprobado**; el estado concreto de esos grupos no se capturó en la corrida fallida.

La corrección posterior conserva TERM/KILL: un sondeo TERM inconcluso avanza a KILL; tras KILL se consulta `ps` acotado a PGID/estado, sin argv, entorno ni usuarios, y únicamente se acepta ausencia de miembros vivos del grupo propio. Denegación real de señales con miembros vivos, salida inválida o verificación inaccesible falla con código 125. Se agregan regresiones EPERM inyectadas, ejecutables en Windows sin permisos especiales; las pruebas POSIX reales permanecen obligatorias. Los logs saneados de fixtures y el resumen de pruebas ahora sobreviven en los artifacts Linux/macOS aun si el smoke falla. Este cambio está pendiente de nueva validación estrecha, **sin push ni corrida posterior** todavía.

## Semántica y límites

- Al reabrir se carga la sesión segura y se revalidan identidad, habilitación y rol en servidor. La autorización no se concede desde rol cacheado.
- Refresh renueva la sesión conforme a Supabase Auth; expiración sin refresh válido no habilita acceso. Una caída temporal conserva la sesión local potencialmente válida, pero permanece sin vista protegida hasta revalidar.
- Logout limpia estado y tokens locales del dispositivo. No garantiza que un JWT ya emitido en otro cliente deje de ser aceptado antes de expirar o de ser revocado por el backend.
- EPT-98/Path B no tiene transferencia de sesión web implementada: no hay Bearer adapter para Next Route Handlers. El canal web no recibe tokens de la app y viceversa.
- HTTP se acepta solo en test mode explícito y con el host local fijado por plataforma (`10.0.2.2:54321` Android, `127.0.0.1:54321` iOS). La validación HTTPS normal no se relaja.

## Riesgos, límites y rollback

Android conserva Docker; iOS ahora depende de los archivos experimentales oficiales ARM fijados. CI debe confirmar bootstrap, migraciones, roles/RLS, conectividad y teardown. Windows no puede ejecutar los binarios macOS ARM, por lo que no se intentó lanzar aquí el backend. Si el runner no permite el stack, reportar el bloqueo sin mocks ni aceptación ficticia. El rollback del feature se limita a archivos EPT-105/workflow; no requiere cambio ni limpieza en producción, Jira o datos compartidos.

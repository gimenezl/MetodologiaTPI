## Semántica y límites

- Al reabrir se carga la sesión segura y se revalidan identidad, habilitación y rol en servidor. La autorización no se concede desde rol cacheado.
- Refresh renueva la sesión conforme a Supabase Auth; expiración sin refresh válido no habilita acceso. Una caída temporal conserva la sesión local potencialmente válida, pero permanece sin vista protegida hasta revalidar.
- Logout limpia estado y tokens locales del dispositivo. No garantiza que un JWT ya emitido en otro cliente deje de ser aceptado antes de expirar o de ser revocado por el backend.
- EPT-98/Path B no tiene transferencia de sesión web implementada: no hay Bearer adapter para Next Route Handlers. El canal web no recibe tokens de la app y viceversa.
- HTTP se acepta solo en test mode explícito y con el host local fijado por plataforma (`10.0.2.2:54321` Android, `127.0.0.1:54321` iOS). La validación HTTPS normal no se relaja.

## Riesgos, límites y rollback

La integración depende de Docker en ambos runners y de Colima en macOS; la corrida CI debe confirmar arranque, migraciones, conectividad y teardown. La estación Windows actual no tiene Docker daemon ni Colima, por lo que no se intentó ejecutar el harness localmente. Si los runners no permiten el stack, reportar el bloqueo sin sustituirlo por mocks ni marcar aceptación. El rollback del feature consiste en revertir solo los archivos de EPT-105/workflow en una revisión posterior; no se requiere cambio ni limpieza en producción, Jira o datos compartidos.
